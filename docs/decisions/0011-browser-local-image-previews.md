# ADR 0011：在浏览器本地持久化图片预览

- 状态：已接受
- 决策日期：2026-07-25
- 补充：[ADR 0009](0009-temporary-image-attachments.md)

## 背景

ADR 0009 规定，网关只在提交图片输入所需的短暂生命周期内保留附件，并在轮次完成后
删除服务端临时文件。当前页面可以直接从用户选择的图片创建预览，但这些内存中的 Blob
URL 会随页面卸载而失效；重新加载页面或线程后，Codex 历史只能表明用户消息包含图片，
不能为浏览器恢复原始字节。

Ask Codex 需要让发送图片的浏览器在重新加载线程后继续显示预览，同时保持服务端临时
附件边界，不让其他浏览器或 Origin 自动获得该预览副本。

## 决策

- 成功启动图片轮次后，在浏览器 IndexedDB 中保存一份本地预览副本。数据按
  `threadId` 和 `turnId` 组成的键保存为有序 Blob 组，并保留消息中图片的原始顺序。
- 浏览器本地预览最多保留 8 张图片、共 40 MiB。超出任一限制时，按写入顺序淘汰最早
  的完整消息组，不部分保留或显示一组图片。每组默认 TTL 为 30 天；过期组在维护时
  删除。
- IndexedDB 只保存恢复预览所需的 Blob、媒体类型、大小、顺序和生命周期元数据。
  不保存 Ask Codex token、宿主机路径、原始文件名或一次性 `attachmentId`。
- Blob URL 不写入持久存储。页面初始化时从 IndexedDB 读取仍有效且已受总量上限约束的
  Blob 组并创建 object URL，在该页面生命周期内管理和撤销这些 URL。
- IndexedDB 不可用、配额不足、写入失败、数据过期或记录被浏览器回收时，发送轮次本身
  不受影响；发送时的内存缩略图仍可在当前页面显示，之后若无法恢复本地记录，历史界面
  再安全降级为现有的图片占位符。
- 预览副本遵循浏览器的同源存储边界，只在同一浏览器配置文件和同一 Origin 中可用。
  清除站点数据、浏览器回收存储、换用其他设备、浏览器或配置文件，或者通过不同 Origin
  访问 Ask Codex 时，历史图片均回退为占位符。
- IndexedDB 中的图片可由同源 JavaScript 访问。Ask Codex 不对本地预览副本额外加密，
  也不把它描述为抵御同源脚本失陷或高权限浏览器扩展的安全保险库。
- ADR 0009 的服务端行为保持不变：图片仍通过受限临时附件提交，网关仍在轮次完成后删除
  服务端文件，不新增持久图片读取端点，也不改变其他原生客户端无法重新附加该文件的
  限制。

## 影响

- 在本地预览记录仍存在时，同一浏览器配置文件通过同一 Origin 重新加载页面或线程，
  或者重启浏览器后，可以恢复已发送图片的缩略图。
- 浏览器而不是服务端决定本地存储的最终可用性。30 天 TTL 和 8 张/40 MiB 上限提供应用
  级边界，但浏览器仍可因用户操作、隐私模式或存储压力提前删除数据。
- 协议历史和 IndexedDB 记录彼此独立；缺少本地记录不会影响线程文本、模型上下文或后续
  轮次，只影响预览呈现。
- 协议、主机名或端口不同都会形成不同 Origin。即使在同一浏览器配置文件中，本地回环
  地址与公共 HTTPS 地址的预览也不会自动共享。
- 服务端不承担持久图片索引、浏览器身份、读取授权或孤立附件垃圾回收，因此既有 token、
  Origin/Host 和临时附件安全边界不扩大。

## 考虑过的替代方案

- 继续只使用内存中的 Blob URL：未采用，因为它只能覆盖当前页面生命周期，页面重新
  加载后无法恢复预览。
- 使用 Web Storage：未采用，因为 `localStorage` 和 `sessionStorage` 只能同步存储
  字符串，Base64 编码会增加体积，并且其常见配额不适合最多 40 MiB 的图片 Blob。
- 使用 Cache API：未采用，因为它更适合按请求和响应管理网络缓存；按线程和轮次维护
  有序消息组、TTL、字节统计和整组 FIFO 淘汰时，IndexedDB 的结构化记录更直接。
- 在服务端持久保存图片并开放受限读取端点：未采用，因为现有 token 和 Origin 是共享的
  应用访问关卡，并不能区分浏览器。满足本需求还需增加浏览器身份、稳定存储、持久索引、
  读取授权、删除语义和垃圾回收，同时会扩大 ADR 0009 刻意限制的服务端文件能力。
