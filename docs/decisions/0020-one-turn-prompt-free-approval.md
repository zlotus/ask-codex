# ADR 0020：为下一次直接轮次提供一次性免审批提示模式

- 状态：已取代；由 [ADR 0022](0022-sandbox-aware-one-turn-auto-run.md) 取代
- 决策日期：2026-08-07
- 修订：[ADR 0002](0002-security-gateway-and-manual-approval.zh-CN.md)

## 背景

Ask Codex 一直把人工审批作为默认执行边界。需求调研、技术路线讨论等低风险对话通常不需要
执行越界操作，但模型仍可能在工作区沙箱内读取文件或运行命令；逐项审批会中断这类连续讨论。
另一方面，把整个线程或浏览器会话永久切换为自动模式，会扩大误操作窗口，也让跨设备状态和
恢复语义变得含糊。

Codex CLI 0.147.0 的稳定 `TurnStartParams` 已支持在 `turn/start` 中提供
`approvalPolicy: "on-request" | "never"`。`never` 只取消审批提示，不会扩大当前 sandbox；
需要审批才能越界的操作会失败。上游策略会影响后续轮次，因此 Ask Codex 不能依赖省略字段来
恢复默认值。实验性的 `thread/settings/update` 不属于本决策的依赖。

## 决策

- Ask Codex 启动时、创建线程和恢复线程时继续使用 `approvalPolicy: "on-request"`，并由网关
  固定 `approvalsReviewer: "user"`。跨设备队列消费也继续固定为手动审批。
- 只在当前选中的已有线程空闲时显示可用的一次性开关。开关状态仅存在于当前页面内存中，
  不写入线程、浏览器存储或跨设备队列；切换线程或进入新建线程流程会清除它。
- 开关启用后，下一次由输入框直接发起的 `turn/start` 显式发送
  `approvalPolicy: "never"`。Working 和请求发送期间禁止修改；该轮次结束、取消、失败，或
  `turn/start` 未返回有效轮次时恢复关闭。启动调用失败时同样失败关闭到手动模式。
- 所有普通直接轮次都显式发送 `approvalPolicy: "on-request"`，不能依赖 app-server 当前保存的
  设置。`turn/steer` 和队列操作不读取也不消费一次性开关。
- 网关只为直接 `turn/start` 接受 `on-request` 或 `never`，拒绝其他值和浏览器提供的
  reviewer，并始终注入用户 reviewer。其他 RPC 的 allowlist、参数重建和失败关闭边界不变。
- `never` 不改变 sandbox。UI 必须明确提示沙箱限制仍然生效；本功能不是 full access，也不是
  自动授予越界权限。
- 轮次结束后不自动调用 `thread/resume` 或实验性设置 RPC 来重置上游状态，因为这会改变审批
  owner 或引入不成熟协议。Ask Codex 通过下一次写入显式携带 `on-request` 恢复自身行为。

## 理由

一次性、默认关闭且只在空闲时可修改的开关，把便利窗口限制在用户明确选择的下一轮。直接在
稳定 `turn/start` 上携带策略不需要增加持久状态，也不会把实验性线程设置 API 引入产品。
每次后续写入显式恢复 `on-request`，避免上游设置的粘性让 Ask Codex 意外延续自动模式。

## 影响

- 需求调研和技术讨论可以连续进行，同时新线程、恢复、队列和后续轮次仍默认手动审批。
- 经过认证但已被攻陷的浏览器现在可以反复请求 `never`；这修订了 ADR 0002 中“浏览器不能选择
  `never`”的原有威胁模型。网关仍限制可调用方法、参数和 sandbox，但不能把该 UI 选择视为
  对恶意浏览器的防线。
- 一个 `never` 轮次结束后，到 Ask Codex 发起下一次显式 `on-request` 写入之前，上游线程设置
  可能仍是 `never`。同一窗口内从其他 Codex 客户端发起轮次的审批行为不由本 UI 保证；自动
  恢复设置会带来 owner 变化，因此不采用。
- 页面刷新或切换线程会清除已启用但尚未消费的开关；同一页面内的普通网关重连会保留这份
  内存状态，Retry/Sync 期间也允许调整，但不会把它同步到其他页面或设备。

## 考虑过的替代方案

- 整个线程或会话切换自动模式：拒绝，因为状态持续时间和跨设备所有权不清晰，误操作窗口更大。
- Working 时允许改变策略：拒绝，因为当前轮次的实际策略已经确定，开关只会制造误导。
- 自动批准部分工具类别：未采用；类别不能可靠表达命令、路径和环境影响。
- 轮次结束后自动 `thread/resume` 或调用 `thread/settings/update`：拒绝，前者会改变 owner，后者是
  实验性 API，而且两者都为简单的一次性 UI 状态引入额外写操作。
