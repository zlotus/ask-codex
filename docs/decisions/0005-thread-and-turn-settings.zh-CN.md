# ADR 0005：分离线程设置与下一轮设置

- 状态：已接受
- 决策日期：2026-07-23
- 修订：[ADR 0006](0006-configured-turn-defaults.zh-CN.md) 仅修订模型和推理强度默认值的来源

## 背景

最初的工具栏将工作目录、沙箱、模型和推理强度作为四项地位相同、可随时编辑的设置呈现。它们的生命周期和风险并不相同。工作目录标识线程的项目上下文。沙箱变更会影响执行策略。模型和推理强度是 app-server 针对下一轮及后续轮次的粘性覆盖值。一直显示这四项控件还会占用大量移动端视口空间。

恢复线程时反复重新发送扁平化的沙箱值，还可能覆盖上游更丰富的权限状态。反过来，隐藏所有权限提示，则会使非默认或完全访问模式的执行状态很容易被忽视。

## 决策

- 准备新线程时选择工作目录，并将其视为线程的项目身份。常规线程 UI 不允许编辑它；切换项目意味着启动新线程。
- 每次打开新线程对话框时均从 `workspace-write` 开始，即使上一线程使用了更宽泛的访问权限。仅允许通过明确的线程设置来修改空闲现有线程的沙箱，并让非默认沙箱状态持续显示在紧凑标题栏中。保持 `externalSandbox` 不变。
- 将模型和推理强度控件放在输入框旁。它们的值应用于下一轮及后续轮次。在轮次进行期间禁用修改。当模型目录标识了默认值时，将“默认”选择解析为明确的默认模型 ID 和推理强度；如果模型目录未标识默认值，则显示“当前”，而不是声称省略字段会重置粘性状态。
- 恢复现有线程时，不要例行重新发送 cwd、模型或扁平化的沙箱。仅在用户明确变更沙箱后才发送沙箱值；在 `turn/start` 时继续发送固定 cwd 和已解析的模型设置。
- 无论这些展示选择如何，网关仍要强制执行 `approvalPolicy: "on-request"` 和 `approvalsReviewer: "user"`。

所选工作目录仍是执行上下文，而不是文件系统安全边界。沙箱执行机制和人工审批仍是相关的安全控制。

## 影响

- 会话界面使用 44 像素高的标题栏，替代多行设置工具栏，尤其改善了移动端视口。
- 线程/项目身份更清晰，不会因会话中途意外编辑 cwd 而发生漂移。
- 完全访问和其他非默认沙箱状态仍然可见，同时无需为常见的 `workspace-write` 情况永久占用空间。
- 客户端必须区分用户明确设置的沙箱覆盖值与恢复线程时仅观察到的值。
- 有意不把现有会话迁移到另一目录作为常规操作；用户应改为启动新线程。

## 考虑过的替代方案

- 保留工具栏中的所有设置：拒绝，因为它浪费移动端空间，并暗示四个值具有相同的生命周期。
- 在线程创建后完全隐藏沙箱状态：拒绝，因为宽泛访问或外部管理的访问状态必须保持可见。
- 在每一轮之前重新发送所有可见设置：拒绝，因为这可能覆盖更丰富的 app-server 状态，并让仅用于展示的被动值表现得像用户明确做出的变更。
- 允许在现有线程中更改 cwd：拒绝，因为这会削弱线程历史、项目指令和未来面向项目的导航之间的联系。
