# ADR 0007：以简体中文作为项目文档的主要语言

- 状态：已接受
- 决策日期：2026-07-24

## 背景

项目文档最初主要使用英文，但项目维护者希望日常阅读、规划和维护都以简体中文进行。同时保留英文版本，有助于英文读者理解项目，也能避免语言切换阻碍协作。

ADR 是不可重写的历史记录。ADR 0001 至 0006 已经以英文接受，因此不能仅为了改变主要文档语言而改写或重命名这些原件。若缺少统一的文件命名和同步规则，双语文档会逐渐产生内容偏差，读者也无法确定默认入口。

## 决策

- 简体中文作为项目文档的主要语言。普通文档的默认文件名承载中文内容，对应英文版本使用同 basename 的 `.en.md` 文件。
- 保留 ADR 0001 至 0006 的英文原件及其文件名不变，并为每份记录提供同 basename 的 `.zh-CN.md` 中文译本。
- 从 ADR 0007 开始，新 ADR 的默认文件名承载中文原件，对应英文译本使用同 basename 的 `.en.md` 文件。
- `docs/decisions/README.md` 作为中文主索引，`docs/decisions/README.en.md` 作为英文索引；两个索引分别链接相应语言版本。
- 对任一双语文档进行语义变更时，必须在同一次变更中同步另一语言版本。纯格式调整或只影响某种语言表达的修正无需制造不相关改动，但两份文档的技术含义必须保持一致。
- 命令、文件名、路径、环境变量、协议方法、字段名、代码标识符及其他需要精确匹配的技术文本保持原样，不作翻译。

本决策只规定项目维护文档的主要语言和镜像方式，不要求翻译源代码、生成文件、依赖内容或协议定义。

## 影响

- 中文读者可以通过默认文件名进入主要文档，英文读者则可通过一致的 `.en.md` 后缀找到对应版本。
- 文档语义变更需要同时维护两种语言，会增加少量审查和维护成本。
- 历史 ADR 的命名方式与新 ADR 不同，但这能同时保留已接受记录的不可变性和未来一致的中文默认规则。
- 评审双语变更时，需要检查技术事实、链接和状态是否一致，而不能只检查语言流畅度。

## 考虑过的替代方案

- 只保留中文文档：拒绝，因为这会不必要地降低英文读者的可访问性，并丢失现有英文资料。
- 继续以英文为主，仅按需添加中文说明：拒绝，因为这不符合项目维护者的主要工作语言。
- 重命名或改写 ADR 0001 至 0006，使中文文件占用默认文件名：拒绝，因为已接受的 ADR 是不可重写的历史记录。
- 不规定同步要求，允许两种语言独立演进：拒绝，因为这会产生相互冲突的项目事实来源。
