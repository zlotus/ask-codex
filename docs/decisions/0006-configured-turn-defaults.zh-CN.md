# ADR 0006：使用配置解析出的轮次默认值

- 状态：已接受
- 决策日期：2026-07-23
- 修订对象：[ADR 0005](0005-thread-and-turn-settings.zh-CN.md)，仅修订模型和推理强度默认值的来源

## 背景

ADR 0005 将工作目录和沙箱的生命周期与下一轮的模型控制分开，但它把空选择显示为“默认”，并从模型目录解析该值。目录中的 `defaultReasoningEffort` 是模型的属性，而不是用户实际生效的 `model_reasoning_effort`。即使 Codex 配置选择了 `max`，这也可能把值标记并发送为 `low`。

让网关直接读取 `~/.codex/config.toml` 会重复实现 Codex 的配置解析器，并忽略优先级更高的覆盖值、profile、系统配置和内置默认值。把完整的 `config/read` 响应转发给浏览器，则会暴露不相关的配置。

## 决策

- 保留 ADR 0005 关于工作目录、沙箱、恢复和审批的决策；仅替换基于模型目录的模型与推理强度默认行为。
- app-server 就绪后，在读取 `model/list` 的同时读取有文档支持的 `config/read` 方法。浏览器不得选择配置层或其他参数；网关始终请求 `includeLayers: false`。
- 在网关处将配置响应投影为有界的 `model` 和 `effort` 字符串。绝不转发来源、配置层、provider、指令、MCP 设置、路径或未知字段。
- 在 UI 中存储实际的模型和推理强度值。不要显示虚构的“默认”选项，也不要将目录条目标记为“（默认）”。即使配置值不在当前模型目录中，也要保留它们。
- 只将 `model/list` 用于提供备选模型、受支持的推理强度选项，以及在有效配置缺少某个值时提供明确的回退值。更改模型时，如果当前推理强度受支持，就保留它；否则选择该模型的目录推理强度或首个受支持的推理强度。
- 如果 `config/read` 失败，应明确呈现该失败，并让模型和推理强度覆盖值保持缺省。不要把读取失败当作空配置，并据此合成模型目录默认值。
- 恢复现有线程所得的值优先于启动默认值。延迟到达的配置响应或重新连接不得覆盖已恢复的线程值或用户选择。
- 网关继续独立强制执行 `approvalPolicy: "on-request"` 和 `approvalsReviewer: "user"`。

## 影响

- 输入区会显示 Codex 从其配置中解析出的同一组明确模型和推理强度，而不是无提示地将它们替换为模型目录默认值。
- 网关会新增一个只读 app-server 方法和相应的结果策略。该响应筛选器属于安全边界；上游 schema 变化时，需要进行聚焦的泄露测试。
- 每次 app-server 连接后都会刷新有效默认值，但这些值只用于初始化尚未被触碰的输入区状态。针对新输入的 cwd 及其项目 `.codex/config.toml` 重新读取配置，仍是有意留待未来的扩展，而非隐式浏览器能力。

## 考虑过的替代方案

- 在 Node 中解析 `~/.codex/config.toml`：拒绝，因为这会重复且不完整地实现 Codex 配置优先级。
- 保留模型目录的“默认”选项：拒绝，因为模型目录默认值与用户的有效配置是不同概念。
- 转发原始 `config/read`：拒绝，因为这会暴露超出狭义模型选择需求的配置。
