# ADR 0021：将一次性免审批提示扩展到新线程首轮

- 状态：已取代；由 [ADR 0022](0022-sandbox-aware-one-turn-auto-run.md) 取代
- 决策日期：2026-08-09
- 修订：[ADR 0020](0020-one-turn-prompt-free-approval.md)

## 背景

ADR 0020 把 `approvalPolicy: "never"` 限定为已有空闲线程的下一次直接轮次。这个边界保持了
默认人工审批，但让新线程出现了不一致：用户在首条消息前已经明确配置了工作目录和 sandbox，
却仍不能为首轮选择同一个一次性模式，只能先完成一次手动轮次。

产品所需的边界实际以 turn 为单位，而不是以线程是否已经存在为单位。每个 turn 都应默认手动，
每个免审批提示 turn 都应由用户当次显式开启。新线程仍必须先完成配置，网关也仍需以手动策略
创建线程；只有随后独立发起的首个 `turn/start` 可以应用当次选择。

## 决策

- 每个 Ask Codex turn 默认使用手动审批。一次性开关不持久化、不自动继承，用户必须为每个需要
  免审批提示的 turn 单独开启。
- 开关只在当前已有线程空闲，或新线程草稿已经完成工作目录和 sandbox 配置时可用。进入新的
  新建线程流程会清除之前的选择；尚未完成配置时不能开启。
- 创建新线程的 `thread/start` 始终使用 `approvalPolicy: "on-request"`，并由网关固定
  `approvalsReviewer: "user"`。如果用户在已配置草稿上显式开启，紧随创建成功后的首个独立
  `turn/start` 才使用 `approvalPolicy: "never"`。
- 草稿获得真实线程 ID 时，当次选择只随正在提交的首轮转换到该线程。这是同一次用户操作的
  连续状态，不构成跨线程继承；切换到其他线程或重新进入新建流程仍会清除选择。
- 轮次完成、取消、失败、启动结果无效，或线程创建/轮次启动失败后立即恢复默认手动。
  Working 和发送期间不能切换。队列、steering、恢复线程及后续 turn 均不继承或消费该选择。
- ADR 0020 的其他边界保持不变：直接 `turn/start` 逐字段重建，网关只接受 `on-request` 或
  `never` 并注入用户 reviewer；`never` 不扩大 sandbox，也不依赖实验性设置 API。

## 理由

以 turn 为唯一的用户授权单位，能让首轮和后续轮次具有相同、可预测的交互：默认都是手动，
需要免提示时都必须点击一次。先以 `on-request` 创建线程，再在独立 `turn/start` 上携带当次
选择，既不会把新线程的长期默认值改成 `never`，也不需要引入持久状态或实验性协议。

## 影响

- 用户完成新线程配置后，可以在发送第一条消息前显式开启一次性免审批提示模式。
- 首轮结束后，第二轮仍回到手动；第二轮若也需要自动审批，必须再次显式开启。已有线程同理。
- 新线程配置对话框不是审批授权面。仅完成配置不会开启 `never`，创建线程本身也始终保持手动。
- 与 ADR 0020 相同，一个 `never` turn 结束后，上游线程设置在 Ask Codex 下一次显式发送
  `on-request` 前可能保持粘性；本 UI 不保证同一窗口内其他 Codex 客户端的行为。

## 考虑过的替代方案

- 保持首轮只能手动：拒绝，因为它按线程年龄制造例外，与逐 turn 显式授权的产品模型不一致。
- 在新线程配置中保存长期自动模式：拒绝，因为它会跨 turn 继承并扩大误操作窗口。
- 让 `thread/start` 直接使用 `never`：拒绝，因为线程创建与首轮执行是两个边界；创建和恢复必须
  继续固定手动，只有独立直接轮次可使用一次性选择。
