# ADR 0001: Use Codex app-server over JSONL stdio

- Status: Accepted
- Decision date: 2026-07-21
- Recorded retrospectively: 2026-07-23

## Context

Ask Codex needs access to Codex-native threads, streamed turns and items,
approvals, models, and account state. Wrapping the terminal UI would couple the
application to presentation text. Codex Desktop private IPC would rely on an
undocumented interface and desktop packaging. Maintaining a separate session
model would make browser history diverge from other Codex clients.

The documented `codex app-server` protocol exposes the required client surface.
Its WebSocket transport is experimental, while JSONL over stdio lets Ask Codex
keep the process and credentials on the trusted host behind its own gateway.

## Decision

Spawn `codex app-server --listen stdio://` as a child process and communicate
using newline-delimited JSON-RPC messages. Initialize it as the Ask Codex client
and expose only a separately governed subset of the protocol to the browser.

Treat bindings generated by the installed Codex CLI as the protocol source of
truth. Compare relevant generated request, response, notification, and union
shapes whenever the CLI changes, and update normalization and focused tests in
the same change.

## Consequences

- Threads remain native to Codex and can be continued across supported Codex
  clients.
- Credentials and the Codex process stay on the host rather than in the browser.
- The gateway must translate lifecycle, request, response, error, and streaming
  behavior reliably.
- CLI upgrades can require coordinated protocol and UI changes because the
  app-server interface evolves.
- Ask Codex does not inherit the terminal UI or Codex Desktop behavior for free.

## Alternatives Considered

- Parse or embed the Codex terminal UI: rejected because it exposes a terminal
  surface and couples behavior to human-oriented output.
- Depend on Codex Desktop private IPC: rejected because it is undocumented and
  would couple the project to a private application boundary.
- Maintain an Ask Codex session database: rejected because it would duplicate
  Codex thread state and weaken cross-client continuity.
- Connect the browser directly to app-server WebSocket transport: rejected for
  now because the gateway is required for policy enforcement and remote-access
  controls.
