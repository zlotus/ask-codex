# ADR 0017：受限文件输入与浏览器本地下载副本

- 状态：已接受
- 决策日期：2026-08-07
- 扩展：[ADR 0009](0009-temporary-image-attachments.md)、[ADR 0011](0011-browser-local-image-previews.md)
- 不改变：[ADR 0013](0013-thread-working-directory-defaults-and-file-download-scope.md)

## 背景

Ask Codex 已能通过临时附件向 `turn/start` 提交 PNG、JPEG 和 WebP 图片，但用户还需要从
输入框选择或粘贴 PDF、文档、压缩包和源码等普通文件。Codex CLI 0.146.0 的 app-server
协议没有面向浏览器原始文件字节的通用输入类型；浏览器也不能提供宿主机路径或构造任意
`additionalContext`。

真实协议验证表明，带 `name` 和 `path` 的 `mention` 输入不适合作为普通本地文件附件；由
网关在已清洗请求中加入受控的 application `additionalContext` 后，Codex 可以使用正常的
本地工具读取临时绝对路径。历史读取仍不会返回可重新读取的原始文件字节，因此提交给模型
的服务端副本和提供给用户下载的浏览器本地副本需要保持不同生命周期。

## 决策

- 输入框使用统一的 `+` 菜单提供图片和普通文件选择。粘贴时，PNG、JPEG 和 WebP 归入图片
  预览，其余文件归入普通文件卡片；图片与普通文件合计每轮最多 4 个，每个最多 10 MiB。
- 普通文件二进制通过复用现有 token、Origin/Host、并发和配额策略的专用 HTTP 端点上传。
  浏览器只获得进程内、一次性的 opaque `attachmentId`，不能提交路径、cwd 或
  `additionalContext`。
- 网关逐字段清洗内部文件输入，消费 ID 后用服务端控制的临时路径构造固定命名空间的
  application `additionalContext`，并明确把文件内容视为不可信用户数据。app-server 的用户
  消息只保存带严格 JSON placeholder 的文本标记，其中包含显示名称、媒体类型和大小，不含
  临时路径或附件 ID。
- 普通文件复用图片附件的资源模型：待提交 ID 最长保留 10 分钟，轮次消费后通常在轮次结束、
  提交失败、app-server 错误或服务关闭时删除，另有 6 小时租约上限；每个 owner 最多 8 个、
  共 40 MiB，全局最多 32 个、共 64 MiB，同时最多 4 个上传。
- 成功启动轮次后，同一浏览器 Origin 在 IndexedDB 中按 `threadId` 和 `turnId` 保存普通文件
  Blob。默认 TTL 为 30 天，最多 8 个、共 40 MiB，超限时按完整消息组淘汰最早记录；删除线程
  同时删除对应记录。只有历史标记的名称、媒体类型、大小与本地记录完全一致时才提供下载，
  否则只显示不可下载的文件占位。
- 本地文件下载直接使用当前浏览器持有的 Blob，不签发 ADR 0013 的 Agent 输出下载
  capability。其他设备、浏览器、配置文件或 Origin，以及本地存储被清除或回收后，都不能
  从 Ask Codex 重新取得原始上传文件。
- Ask Codex 不承诺理解每种文件格式。它只把受限临时路径交给 Codex；Codex 是否能解析文件
  取决于当前环境可用的工具和模型行为。

## 影响

- 用户可以从统一入口选择或粘贴多种本地文件，发送后的用户消息保留稳定的文件名和大小
  呈现；同源本地副本存在时可下载原文件。
- 网关增加了受限上传面，但没有变成按浏览器路径读取宿主机文件的通用文件服务，也没有扩大
  Agent 消息下载范围。
- Codex 读取的是短期服务端副本。轮次结束后，原生客户端不能依赖历史中的临时路径重新附加
  文件；浏览器本地副本也不向模型、其他客户端或其他 Origin 提供持久读取能力。
- 伪造或损坏的历史 marker、元数据不一致、IndexedDB 不可用或本地记录缺失只会使下载降级，
  不影响线程文本和后续轮次。

## 考虑过的替代方案

- 使用 `mention` 输入携带文件：未采用，因为当前协议和真实验证不能为普通本地文件提供可靠的
  读取语义。
- 让浏览器提交路径或自定义 `additionalContext`：拒绝，因为这会绕过 RPC 参数重建并增加
  宿主机路径和提示注入面。
- 把文件编码进 WebSocket：拒绝，因为 Base64 和 JSON 会扩大内存与消息体并越过现有上限。
- 永久保留服务端上传并向所有客户端开放历史下载：未采用，因为这需要浏览器身份、持久索引、
  引用跟踪、删除语义和垃圾回收，并会扩大服务端文件能力。
- 复用 ADR 0013 的 Agent 输出下载 capability：拒绝，因为用户上传的本地副本不是由已完成
  Agent 消息和权威 `thread.cwd` 派生的宿主机输出。
