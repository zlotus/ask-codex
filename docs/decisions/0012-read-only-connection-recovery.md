# ADR 0012：通过只读重同步恢复连接

- 状态：已接受
- 决策日期：2026-08-02
- 扩展：[ADR 0002](0002-security-gateway-and-manual-approval.zh-CN.md)

## 背景

移动浏览器休眠、网络切换、WebSocket 断开或 `codex app-server` 子进程重启，都可能使
浏览器暂时失去实时通知。连接恢复时，浏览器无法可靠判断断线前发出的写请求是否已经被
Codex 接受；直接重放可能重复创建轮次、重复响应审批或重复改变线程元数据。

`thread/resume` 也不是普通的读取操作。它会恢复线程并可能影响审批请求应路由到哪个
客户端。后台监控或自动恢复如果调用它，可能从主动使用该线程的其他客户端手中改变线程
owner。另一方面，只恢复 WebSocket 而不核对当前线程快照，会让界面在遗漏通知后错误地
显示轮次、审批或发送状态。

## 决策

- 将传输重连、Codex 子进程重启和当前线程重同步作为三个可见阶段。WebSocket 故障只重建
  浏览器连接；Codex 子进程错误可由有界的只读探测触发网关重启。
- Codex 在一次已经成功 ready 的连接生命周期之后再次 ready 时，若当前线程已经完整加载，
  浏览器在重新允许发送前通过受限的 `thread/read` 和 `thread/turns/list` 读取快照。重同步
  期间有界缓冲实时通知，并在快照协调后按顺序应用，避免读取与通知之间的竞态。
- 首次 ready 只建立基线，不执行多余的恢复读取。若断线打断了线程的首次加载，则显示明确
  的重试入口，由用户重新选择正常加载流程；自动恢复不得调用 `thread/resume`。
- Activity 等只读跨线程视图和后台刷新只能调用网关明确允许、参数经过重建且结果经过投影的
  只读方法。只有用户明确选择一个线程时，才进入既有的正常恢复流程并接受其 owner 语义。
- 不自动重放状态未知的写请求，包括 `turn/start`、审批响应、中断、重命名、归档和删除。
  浏览器可以保留尚未确认的输入草稿，但由用户决定是否重新提交。
- 断线时清理浏览器中可能过期的审批界面；仍未解决的 app-server 请求由网关按既有审批
  owner 和重路由规则重新投递，而不是由浏览器猜测并重发响应。
- 快照重同步失败时继续禁用发送，并提供只执行同一组受限读取的重试。失败不得降级为假定
  当前状态已经同步。

## 影响

- 自动恢复可以重新建立可验证的当前线程状态，同时不会重复产生具有实际影响的操作。
- 只读 Activity 和其他监控界面不会因后台观察而认领线程或改变审批路由。
- 用户可能需要手动重新提交一个在断线前未确认的请求；这是避免重复写操作的显式取舍。
- 恢复需要额外的有界读取和通知协调逻辑。同步失败会暂时阻止发送，但仍允许编辑草稿和
  再次执行只读重试。
- 未来新增离线队列、轮次 steering 或跨设备消息投递时，必须另行定义幂等键、确认语义和
  owner 规则；本决策不授权自动写重放。

## 考虑过的替代方案

- 连接恢复后重放所有待定 RPC：未采用，因为浏览器无法证明上游没有已经执行写操作，重放
  会造成重复轮次、审批响应或元数据变更。
- 在后台调用 `thread/resume` 恢复每个运行中线程：未采用，因为它不是纯读取，并可能改变
  多客户端之间的审批 owner。
- WebSocket ready 后立即恢复发送而不读取快照：未采用，因为断线期间遗漏的通知可能使界面
  对当前轮次、审批和可发送状态作出错误判断。
- 所有恢复都要求手动刷新页面：未采用，因为传输和只读状态核对可以在明确边界内安全自动化，
  且移动浏览器的短暂休眠不应强制丢弃本地草稿。
