# ADR 0010：新线程使用 app-server 默认历史契约

- 状态：已接受
- 决策日期：2026-07-25
- 取代：[ADR 0008](0008-paginated-thread-history.md)

## 背景

ADR 0008 根据 Codex CLI 0.145.0 的实验性 schema，让网关为所有新线程注入
`historyMode: "paginated"`。实际的新线程首轮测试表明，schema 中存在该字段并不代表
当前运行环境完整支持分页线程写入；首轮可能以
`paginated_threads is not supported yet` 失败。`thread/start` 本身可以成功，因此仅探测
线程创建也无法发现这个问题。

app-server 没有提供可在启动轮次前可靠判断该能力的声明。`thread/start` 和
`turn/start` 也没有幂等键；在错误或超时后自动重试，可能产生重复线程、重复轮次或孤立
线程。带图片的失败路径还会消费并释放一次性附件，因此不能安全地把原请求转发到另一个
隐式创建的线程。

## 决策

- 网关不再为 `thread/start` 发送实验性的 `historyMode` 字段，由 app-server 选择默认
  历史契约。浏览器仍不能提供或选择该字段。
- 不根据版本号、错误文本或一次 `thread/start` 成功来推断分页写入能力，也不自动重试
  `thread/start` 或 `turn/start`。
- 继续以严格受限的方式开放 `thread/items/list`，并根据 Codex 返回的
  `thread.historyMode` 恢复已有分页线程。默认或 `legacy` 线程继续使用有界的整轮详情
  重试和摘要降级。
- 不迁移、重写或自动删除已有线程。将来只有在 app-server 提供明确能力声明并完成真实
  首轮验证后，才重新考虑为新线程选择分页历史。

## 影响

- 新线程不再因 Ask Codex 强制选择一个运行环境不完整支持的实验契约而无法启动首轮。
- 使用 app-server 默认 `legacy` 契约的新线程，如果单个完整轮次超过网关上限，仍可能
  只能显示摘要。
- 已有或由其他客户端创建的分页线程仍可使用条目级恢复，不需要删除相应的读取策略和
  客户端实现。
- 修复部署前已经创建且无法启动首轮的空分页线程不会自动迁移；用户应新建线程。

## 考虑过的替代方案

- 显式发送 `historyMode: "legacy"`：未采用，因为该字段本身仍是实验性接口；省略字段能
  保持 app-server 对默认持久化契约的所有权。
- 遇到特定错误后自动重试：拒绝，因为请求不具备幂等性，而且错误或超时不能证明第一次
  请求没有产生状态。
- 按 CLI 版本启用分页：拒绝，因为 schema 或版本存在不能证明完整的首轮写入路径可用。
- 向浏览器暴露历史模式：拒绝，因为持久化契约仍属于网关和 app-server 的策略边界。
